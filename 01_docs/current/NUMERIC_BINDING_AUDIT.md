# 数值规则核对

## 当前实现的确定行为

| 项 | 当前规则 | 来源与证据等级 |
|---|---|---|
| 参考版本 | 仓库 VTM `version.h` 为24.0 | `vtm10` profile名指10位参数，不是VTM10.0版本 |
| 参数 | bit_depth=10，extended_precision=false，动态范围15 | 工程绑定；不是赛题已确认的SPS配置 |
| 轴顺序 | V后H | 用户提供专家答疑记录支持；原生adapter也按此调用 |
| V阶段 | `(sum+64) >>> 7`，裁剪到[-32768,32767] | VTM原语的调用参数与已冻结profile |
| H阶段 | `(sum+512) >>> 10`，同样signed16裁剪 | 在选定位深/动态范围下的工程绑定 |
| LFNST | shift7、加64、signed16裁剪；按扫描布局 gather/scatter | 附件系数与冻结布局模型；square4x4/8x8仅8输入项的规则另列待确认 |
| 最终10位 | SAT10到[-512,511]，二进制补码输出 | 专家答疑确认signed10编码；没有确认SAT10优于取低10位 |
| 输入支持区 | DCT2-64每轴32项，DCT8/DST7-32每轴16项；LFNST按4/8支撑 | VTM/工程模型约定；区外系数按0处理 |
| 空间输出 | 完整W*H；每beat按光栅顺序4点 | 赛题明确要求；输入zero-out不等于空间输出zero-out |

## 独立参考到底证明了什么

`vtm_full_spatial_oracle.cpp` 链接仓库原版 TrQuant_EMT.cpp、RomTr.cpp，执行原生DCT2/DCT8/DST7计算。
它由工程adapter提供输入支持掩码、shift7/10及signed16范围。LFNST预处理先在Python中完成，再送入原生主变换。
因此它能独立检验主变换算术与全空间重建，不能独立证明LFNST预处理、参数选择或最终SAT10符合官方金标准。
LFNST另有1088个原语向量和布局测试；这些是选定规则下的验证，不消除规范歧义。

原498个用例保留，本轮另增169个LFNST-off合法配置的稀疏signed16极值场景，固定seed=20261104。
包括-32768、-16385、-513、-1、1、511、16384、32767，覆盖输入支持区内外；总计667个用例、352896个主变换输出值。
最终10位RTL比较还经过所选SAT10映射，不能将映射后的比较称为VTM原生signed10结果。

## 可用于澄清的最小数值例子

- 4x4 DCT2，DC=512：当前V/H规则下所有16点为16。
- 4x4 DCT2，DC=32767：V/H后wide结果为1024；SAT10给511，取低10位给0。
- 4x4 DCT2，DC=-32768：wide结果为-1024；SAT10给-512，取低10位给0。
- square4x4/8x8 LFNST：仅在第9个扫描输入位置写非零值，可区分“只取前8项”与“使用16项”两种解释。

这些是区分规则的例子，不把任一未获确认的解释当作官方答案。
官方状态保持 NOT_PROVEN；待澄清项见 SPEC_CLARIFICATIONS.md。
