## 五、已知限制（仍然成立）

- 数值正确性依赖项目向量集（369 case），UVM 层未独立实现变换模型。
- 随机化的对象是用例抽取/顺序/间隔，不是描述符本身的随机生成。
- 两个 agent 按管脚组拆分（激励 / 反压），**不是两路 DUT 通道并发**。
- 复位只测了"处理途中拉低 rst_n"一种时序，未覆盖复位抖动或多拍复位。
- 覆盖是 DUT 单模块口径（991 条语句），未与 D1 的 UCDB 跨套件合并。
- 分支缺口有一次账目对不齐：`vcover` 摘要 144 miss、明细 CSV 145 行，差 1 行未查明。
- 条件/表达式的块内缺项合计与汇总口径有粒度差（44 / 56），未对齐。
- L616 / L651 的表达式覆盖率与同行语句命中数矛盾，判不清是内联还是报表问题。
- **X 类检查从未在真实 DUT 上触发**：22 例里 `x_errors` / `sig_errors` /
  `in_errors` / `vld_stall_guard` 全为 0，有效性只由合成激励与反向自检支撑。
- **52/54 是旧覆盖模型的测量值**，口径里含形状/配置四组 + `cg_sat`（输出边界分类）
  + `cg_depth`（背压深度）+ `cg_phase`（停顿阶段），**不是纯形状/配置覆盖**。
  `cg_sat` 的分类实现本身有错误（"等于边界"≠"发生裁剪"、`foreach` 遍历 40 个 bit
  索引、正负边界互相覆盖），B 阶段替换后重新报告；旧数字不与新数字比较百分比。
- 11 个负向用例的 `native_errors_allowed = 1` 是防既有协议错误的预算，不是
  "允许错一次"的许可。
