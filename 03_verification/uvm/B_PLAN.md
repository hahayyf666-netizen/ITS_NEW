## 1 B1：grant profile 的执行与衔接

### 1.1 现状（已核实，附坐标）

`its_uvm_pkg.sv:1166` `its_grant_driver`：

- `drive()` 每个下降沿把 `remaining` 递减，减到 0 时调用
  `revert_to_default()`（`:1213–1219`），**到期即回默认**。
- `revert_to_default()`（`:1201–1207`）只复位 `always_grant / light_mod /
  light_off / deep_period / deep_len`，**不清 `hold`**。
- `hold` 是深度停摆的倒计数（`:1224–1229`），只有 `apply_profile()` 会把它清零
  （`:1198`）。

### 1.2 两个问题

1. **段间插入默认配置。** 一条 profile 到期后，到下一条 item 真正被 driver 取走
   之间，DUT 处在默认 profile 下。这段空隙长度取决于序列的 `start_item` /
   `finish_item` 延迟，不由用例控制。结果：同样名义上的"三段窗口"，实际波形
   取决于调度，用例的行为不可复述。
2. **`hold` 跨过期存活。** 若在 `hold > 0` 期间到期，`revert_to_default()` 把
   `deep_len` 改回 8 却保留剩余 `hold`，于是默认配置下又追加一段非零停摆。
   这属于"段已结束但扰动还在"。

### 1.3 倾向改法（待确认）

- 到期**不做任何事**：当前 profile 继续有效，直到下一条 item 到达才被
  `apply_profile()` 替换。删除 `drive()` 里的到期 `revert_to_default()` 调用。
- 新增显式 `restore_default()`：复位四个参数**并清 `hold`**，由序列在
  `body()` 末尾调用一次。
- 因此 `its_grant_profile_sequence::body()`（`:709–720`）三段窗口后补一次
  restore；`single` 分支（`:710–713`）同样补。

**要你确认的点**：到期后"保持当前 profile"，还是"回到一个明确的、由用例指定的
守卫 profile"？前者改动最小；后者更适合表达"段与段之间应当无扰动"，但需要给
每条 profile 加一个衔接字段。

### 1.4 验收判据

- 反例先行：构造一条 `hold > 0` 时到期的 profile，修前应能观察到过期后仍有
  非零停摆；修后用同一激励看不到。
- 三段窗口之间的 req 波形与"无空隙"假设一致：段边界上不出现默认 profile 的
  `cyc % light_mod` 图案。
- `tail_stress`（`+TAIL_STALL=600`）的停摆起止可复现，且与用例内注释一致。
- 全量 22 例行为不变（除预期受影响的覆盖数字外，判定全部 PASS）。
- 检查器判定不变：B1 只改激励，不改判定；22 例的 `status` 与 A 阶段一致。

## 2 B2：输出值域覆盖模型

### 2.1 现状

现有 7 个 covergroup（`its_uvm_pkg.sv:1587–1756`）全部在**形状或配置**域：
`cg_shape`(25) / `cg_xform`(9) / `cg_lfnst_mode`(3) / `cg_lfnst_idx`(4) /
`cg_sat`(3) / `cg_depth`(4) / `cg_phase`(6)，合计 54 bin，合并命中 52。

**没有任何一个 covergroup 看输出值**。也就是说：DUT 的数字输出域（含饱和行为）
目前完全没有功能覆盖。

### 2.2 要补的两个点

| 覆盖点 | 采样时机 | 采样对象 | 为什么 |
| --- | --- | --- | --- |
| `out_rail` | 每个输出 beat | 最终 10 位有符号结果落点（−512 / +511 / 中间） | 输出值域是否被真正走过 |
| `clip_signed10` | 每个 `horizontal_result_fire`（`unified_its_wrapper.sv:1788`） | `final_adapter()`（`:1086–1101`）的钳位是否生效 | 饱和分支是否被执行过 |

`final_adapter()` 只有 `FINAL_SATURATE != 0` 且 `value_i > 511` 或 `< -512` 时
才钳位；否则直接截低 10 位。**这个分支在现有 22 例里是否命中过，目前没有任何
记录**——这正是 B2 要回答的问题之一。

### 2.3 与原草案的差异（需要你定）

A 阶段方案里写的是"组数 7→8，bin 54→55"。按上一节的实际需要，两个覆盖点
至少对应 2 个 bin（`out_rail` 若三分则 3 个），**54→55 这个数字与设计不一致**。
可能是草案只算了其中一条。实现前需要定：

1. `out_rail` 分几档：2 档（贴轨 / 非贴轨）还是 3 档（−512 / +511 / 中间）？
2. `clip_signed10` 是并入新组，还是作为 `out_rail` 的一个 bin？
3. **X 值**按约定不进 bin，另作完整性计数器（延续 A 阶段 D2 的四态处理）；
   这一条是否仍然算数？

我倾向于：新建 `cg_out_value`，`out_rail` 三分 + `clip_signed10` 两分（钳位/未钳位）
共 5 bin，组 7→8、bin 54→59。但这会让旧口径的 52/54 无法直接比较——见 §3.3。

### 2.4 验收判据

- 运行 `vsim` 后能从合并覆盖报告里读出每个新 bin 的命中数，且与手工在波形/日志
  里数的次数一致（至少对一组用例做核对）。
- 若某个 bin 命中为 0，必须给出"未命中"的归因：是向量集里没有超 ±511 的值
  （那就是激励缺口，需要新向量），还是 `FINAL_SATURATE` 被关（那是参数配置），
  还是逻辑上不可达（需要说明）。**不接受"没命中就是设计如此"这种结论。**
- 新 bin 的添加不改变既有 54 个 bin 的命中状态——除 `cg_phase` 那 2 个已知
  不可达项外，其余仍应全中。
