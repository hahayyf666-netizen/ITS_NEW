## 1 B1：grant profile 的执行与衔接

### 1.1 现状（逐条核实，附坐标）

`its_grant_driver::run_phase`（`its_uvm_pkg.sv:1237`）：

```systemverilog
forever begin
    seq_item_port.get_next_item(req);
    apply_profile(req);
    seq_item_port.item_done();     // 立即应答
end
```

1. **`item_done()` 立即返回，不等 `duration_cycles`。** 三段 `send()`
   （`:717–719`）连续执行，`apply_profile()`（`:1191`）每次都覆盖参数并重置
   `remaining`。因此**只有最后一段（`3/5, 24/10, 6000`）真正生效**，前两段的
   6000 / 3000 拍从未执行。
   （v2 此处误引成 `5/9, 32/4, 6000`——那是**第一段**；最后一段是 `send(1'b0, 3,
   5, 24, 10, 6000)`，即 `light=3/5`、`deep=24/10`、`dur=6000`。2026-11-13 更正。）
2. **末拍提前切换。** `drive()`（`:1213–1219`）先在同一个下降沿递减 `remaining`，
   减到 0 就调 `revert_to_default()`，**之后**才生成本拍 `req`。所以名义 N 拍里
   只有 N−1 拍是原 profile。
3. **深停顿长度不是 `deep_len`。** 触发拍（`:1227–1229`）先拉低并置
   `hold = deep_len`，随后 `hold > 0` 分支（`:1224–1226`）再低 `deep_len` 拍。
   实际低电平拍数 = 1 + `deep_len`；**且 `hold` 用尽后同一拍的轻停顿规则或下一次
   深停顿可能立刻再拉低**，所以"连续低电平长度"不等于 `deep_len`。
4. **`revert_to_default()`（`:1201–1207`）不清 `hold`**，残留 `hold` 会带进下一段。
5. **`duration_cycles` 是非 `rand`、默认 0（`:197`），却受 `c_dur { inside
   {[100:8000]} }`（`:205`）约束。** 目前没有任何代码 `randomize()` 这个 item
   （`send()` 直接赋值），所以是**潜伏**问题。失败条件已实测（ModelSim，
   见 `closure_audit/measure_rand_constraint.txt`）：

   ```
   duration 保持默认 0   → randomize() FAILED（vsim-7084，无解）
   duration 预置 600     → randomize() ok
   ```

   所以准确说法是**默认值下随机化必失败，预置成满足约束的值则可以成功**；不是
   "一旦随机化就失败"。仍必须在本阶段处理。

### 1.2 契约（已固定，不再留选项）

| 项目 | 固定规则 |
| --- | --- |
| 执行完成 | driver 完整执行该段 N 个**约定采样周期**后才调 `item_done()`；sequence 不另设计时。三段分别 6000 / 3000 / 6000 |
| 计数基准 | 到期计数以**后续 DUT 采样的上升沿**为准：driver 在下降沿驱动，第 N 个上升沿完成后才 `item_done()`，**下一下降沿**才切换请求波形 |
| 段间 | **固定插入 1 个完整守卫周期**（首版口径）。此后不再追求无缝切换 |
| 到期 | 清除 `hold`，进入守卫；下一段由 driver 在规定下降沿启动 |
| 守卫 | `req` 持续为 1，守卫周期必须为 1；下一段第一拍按下一段规则驱动，**合法拉低不算衔接错误** |
| `deep_len` | **表示包含触发拍的深停顿长度**；触发拍之后剩余 `deep_len − 1` 拍 |
| 有限事务 | `duration_cycles` 改为 `rand`，合法默认值，保留 `[100:8000]` 约束；**不再用 0 表示永久**。持久守卫配置与有限事务分开 |
| 复位期间 | 守卫 `req = 1`，**暂停事务执行计数并清除 `hold`**；复位释放后继续剩余周期 |
| 全局相位 | `cyc` 继续随时钟递增，**不随 profile 或复位归零** |
| 守卫驱动权 | 守卫请求由 driver 驱动；sequence 不直接改管脚、不改 driver 内部状态 |

`deep_len` 的验证要避开叠加：`hold` 用尽后轻停顿规则或下一次深停顿可能立刻再
拉低 `req`，所以**连续低电平长度不一定等于 `deep_len`**。验收时要么选不会叠加的
配置，要么分别记录深停顿事件与真实管脚波形。

### 1.3 验收判据

- **逐拍检查首拍、末拍与段边界**，不能只看日志里的配置值发布。
- 三段实测长度 = 6000 / 3000 / 6000 个**上升沿**（附计数脚本）。计数以 DUT 采样的
  上升沿为准，不用 driver 自报的执行计数。
- **独立检查器在上升沿核对实际 `req`**，而不是读 driver 的内部计数：driver 在
  下降沿用非阻塞赋值，同一沿的普通观察可能读到旧值。
- 守卫周期 `req` 必须为 1；**下一段第一拍按下一段规则驱动，合法拉低不算错误**。
- 深停顿：按 §1.2 的定义核对，且选择不叠加其他停顿的配置，或分别记录深停顿事件
  与实际波形；覆盖 `deep_len = 1` 与 `deep_len = 上限` 两个边界。
- 复位期间行为符合 §1.2（守卫、暂停计数、清 `hold`、释放后继续剩余周期），并验证
  选择本身（不是只写进注释）。
- **profile 执行过不等于压到了 DUT**：记录目标 DUT 状态与停顿的实际重叠。
  `tail_stress` 若只在复位或 scrub 期间暂停，不能声称测到了目标 tail 路径。
- 原有 22 例判定不变（除新增用例外）。

## 2 B2：输出值域覆盖模型（替换 `cg_sat`）

### 2.1 现状（v1 在此写错，此处更正）

`its_out_coverage::write()`（`:1767`）**已经在采样输出数据**：

```systemverilog
foreach (item.data[i]) begin
    if (item.data[i*10 +: 10] == 10'h1FF) cls = 1;
end
foreach (item.data[i]) begin
    if (item.data[i*10 +: 10] == 10'h200) cls = (cls == 1) ? 0 : 2;
end
cur_sat = cls;  cg_sat.sample();
```

`cg_sat`（`:1724`）有 `none / pos / neg` 三个 bin，属于输出值分类。所以准确的说法是：
**已有输出边界值覆盖，但三处实现有错误，且不能证明真正发生了 signed10 饱和裁剪。**

| 缺陷 | 内容 |
| --- | --- |
| 概念混淆 | 把"输出 lane 等于边界"当成"发生了裁剪"。`+511` / `−512` 本身就是合法值，不是越界 |
| 遍历错误 | `item.data` 是 `logic [39:0]`，`foreach` 遍历 **40 个 bit 索引**；只有 `i=0..3` 落在合法 lane 上，`i=4..39` 是越界 part-select（返回 X） |
| 分类互斥 | 分类**依赖负边界 lane 的数量**，且丢失正边界信息：正边界 + 恰 1 个负边界 → `cls` 从 1 改回 0，判成 `none`；再来第 2 个负边界 → 又变成 `neg`。同一 beat 同时含正负边界时结果取决于负 lane 个数 |

**因此 B2 是替换旧 `cg_sat`，不是保留它再往上追加覆盖点。**

### 2.2 新模型（采纳审核建议，目标 bin 合计 56）

| 新组 | 采样单位 | 目标 bin |
| --- | --- | --- |
| `out_rail` | 每个被接收输出 beat 的四个 lane，**逐 lane** 采样 | `−512`、内部值 `[−511:510]`、`+511`，共 3 个 |
| `clip_signed10` | 每次有效 H 结果的四个**裁剪前** `signed [15:0]` lane | 正越界 `> 511`、负越界 `< −512`，共 2 个 |

逐 lane 采样后，同一 beat 同时含 `+511` 与 `−512` 会分别命中两边，不再被迫塞进
一个互斥的 beat 分类。裁剪也区分正负，**不用"钳位/未钳位"二分**——那样只测到一个
方向也可能显示全覆盖。

**口径推导**：`54 − 旧 sat 3 + out_rail 3 + clip 2 = 56`；按两个独立 covergroup
实现，组数 `7 − 1 + 2 = 8`。

（v1 提的 59 是"54 + 5"，保留了本应被替换的旧三项，已作废。55 对应"`out_rail`
只设正、负两个命中目标"的另一份清单，也不是算术错误——数字取决于模型，不能先定
数字再凑定义。）

**这 56 是项目自定义的目标 bin 汇总口径，不等于工具对 coverpoint/cross 的原生
加权覆盖率。** 报告时必须写清是哪一套口径。

### 2.3 采样规则

- **观测点**：`unified_its_wrapper.sv:1788` `horizontal_result_fire` 有效时，读取
  `kernel_out_data` 的四个 `signed[15:0]` 实参——这正是 `final_adapter()`
  （`:1086`）的入参。
- **采样机制（落地，不留作"用正确的方式"）**：在 `its_if` 里加 clocking block，
  输入偏斜用 `#1step`，在该上升沿之前采样 `horizontal_result_fire` 与四个
  `signed16` lane，保证读到的是这一拍被 RTL 消费的值，而不是 NBA 更新后的下一拍。
  TB top 已有层级引用先例（`its_uvm_tb.sv:47–51` 的 `dut.scrub_active` 等），
  新 tap 用同样方式连接，**不改 RTL**。
- **可见性先验证**：`dut.kernel_out_data`、`dut.horizontal_result_fire` 是否可直接
  层次引用，先写一条最小探针确认，再依赖。
- **防错一拍**：构造相邻两拍数据不同的定向检查，证明采到的不是下一拍。
- **仅在 `FINAL_SATURATE != 0` 时**把越界记作"发生裁剪"（本 TB 是
  `FINAL_SATURATE(1)`，见 `its_uvm_tb.sv:21`）。
- `+511`、`−512` 是合法边界，**不是越界**；`> 511`、`< −512` 才算裁剪。
- 四态数据**不能先转二态再判断**。
- 内部裁剪事件与外部输出接收事件**不同**：复位丢弃在途 TU 时两者次数不必相等，
  不能拿"次数相等"当验收条件。
- X/Z 不进入数值 bin，同时**报完整性错误并阻断通过**；复位与无效数据窗口明确屏蔽
  （不是"只计数、不影响判定"）。

### 2.4 验收判据

**分类器定向检查**（在 SystemVerilog 里做，不走 Python 数值模型）：

| 项 | 要求 |
| --- | --- |
| 边界值 | `511`、`512`、`−512`、`−513` 四个值分别落对 bin |
| 同组组合 | 仅正越界、仅负越界、两者都有、都没有 |
| 四态 | 含 X/Z 的 lane 不进入数值 bin，且触发完整性错误 |
| 逐 lane | 同一 beat 内四 lane 不同取值分别计数，不互相覆盖 |

X/Z 反例**必须作用于实际的 SystemVerilog 四态采样链**：分类逻辑最终跑在 SV 的
coverage 组件里，用 Python 数值分类测试证明不了四态语义。

**真 DUT 验收**：

- 用合法输入命中正裁剪与负裁剪各至少一次，并核对最终 signed10 输出。
- **不能用合成激励的分类器自检替代真 DUT 的裁剪覆盖。**
- 若零命中：可达目标必须补合法向量命；只写"激励缺口"不能宣布 B2 完成。
  确实不可达时，按证据调整目标并在文档里说明理由。

**汇总口径必须同步改**（替换覆盖组不只是改 covergroup）：

| 位置 | 要改什么 |
| --- | --- |
| `run_regress.py:48` `CG_TOTALS` | 删 `"sat": 3`，加 `out_rail: 3`、`clip_signed10: 2` |
| `run_regress.py:700` `coverage_bins()` | 按 `cg.<group>.<bin>` 解析，组名变了要能取到 |
| `run_regress.py:718` `merge_coverage()` | **未知组会被静默跳过**（`if total:` 才计入）——不更新 `CG_TOTALS` 不会报错，只会让新组悄悄消失，必须显式核对新组出现在报告里 |

### 7.1 已实测、不再靠推断的一条

`duration_cycles` 的约束行为用 ModelSim 实测（`tmp_rand_check/t.sv`，

duration 保持默认 0  → randomize() FAILED（vsim-7084：No solutions exist）
