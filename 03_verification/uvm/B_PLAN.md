## 1 B1：grant profile 的执行与衔接

### 1.1 现状（逐条核实，附坐标）

`its_grant_driver::run_phase`（`its_uvm_pkg.sv:1237`）：

```systemverilog
forever begin
    seq_item_port.get_next_item(req);
    apply_profile(req);
    seq_item_port.item_done();     // 立即应答
end
```

1. **`item_done()` 立即返回，不等 `duration_cycles`。** 三段 `send()`
   （`:717–719`）连续执行，`apply_profile()`（`:1191`）每次都覆盖参数并重置
   `remaining`。因此**只有最后一段（`5/9, 32/4, 6000`）真正生效**，前两段的
   6000 / 3000 拍从未执行。
2. **末拍提前切换。** `drive()`（`:1213–1219`）先在同一个下降沿递减 `remaining`，
   减到 0 就调 `revert_to_default()`，**之后**才生成本拍 `req`。所以名义 N 拍里
   只有 N−1 拍是原 profile。
3. **深停顿长度不是 `deep_len`。** 触发拍（`:1227–1229`）先拉低并置
   `hold = deep_len`，随后 `hold > 0` 分支（`:1224–1226`）再低 `deep_len` 拍。
   实际低电平拍数 = 1 + `deep_len`。
4. **`revert_to_default()`（`:1201–1207`）不清 `hold`**，残留 `hold` 会带进下一段。
5. **`duration_cycles` 是非 `rand`、默认 0（`:197`），却受 `c_dur { inside
   {[100:8000]} }`（`:205`）约束。** 目前没有任何代码 `randomize()` 这个 item
   （`send()` 直接赋值），所以是**潜伏**问题；一旦有人随机化就会失败。必须在本
   阶段一并处理，不能继续挂着。

### 1.2 契约（按审核意见固定）

1. **执行完成语义**：driver 完整执行该段的 N 个约定采样周期后，才调用
   `item_done()`；**sequence 不另设一套计时**。三段分别执行 6000 / 3000 / 6000 拍。
2. **到期行为**：到期回到**明确的守卫 profile**（建议 `req = 1` 持续），**清除
   残留 `hold`**；下一段在约定边界接管。守卫请求由 driver 驱动，**sequence 不直接
   改管脚、不改 driver 内部状态**。
3. **边界记录**：若段与段之间确实存在间隙，**明确记录其长度**，不依赖
   delta-cycle 调度碰巧衔接。
4. **计数语义**：改为"已执行拍数"递增，执行满 N 拍后再切换，消除 §1.1 第 2 条
   的末拍提前切换。
5. **`deep_len` 定义**：明确它是"触发拍之后额外的低电平拍数"（即总长 1+`deep_len`）
   还是总长；选定后写进注释并加断言，逐拍可核对。
6. **`duration_cycles`**：持久守卫配置与有限事务分开。有限事务用合法默认值并给出
   一致的随机约束（或改为 `rand` 使约束可用）。
7. **相位**：本轮保留全局 `cyc` 相位，不额外改变；**复位期间是否计入 duration**
   必须固定并验证；在途 profile 在复位期间如何处理也要写明。

### 1.3 验收判据

- **逐拍检查首拍、末拍与段边界**，不能只看日志里的配置值发布。
- 三段实测长度 = 6000 / 3000 / 6000 拍（按负沿采样计数，附计数脚本）。
- 段边界处 `req` 连续为 1（守卫），不出现默认 profile 的
  `cyc % light_mod` 图案。
- 深停顿实测低电平长度与 §1.2 第 5 条选定的定义一致，并覆盖
  `deep_len = 1` 与 `deep_len = 上限` 两个边界。
- **profile 执行过不等于压到了 DUT**：记录目标 DUT 状态与停顿的实际重叠。
  `tail_stress` 若只在复位或 scrub 期间暂停，不能声称测到了目标 tail 路径。
- 22 例判定全部 PASS（除新增用例外），检查器判定不变。

## 2 B2：输出值域覆盖模型（替换 `cg_sat`）

### 2.1 现状（v1 在此写错，此处更正）

`its_out_coverage::write()`（`:1767`）**已经在采样输出数据**：

```systemverilog
foreach (item.data[i]) begin
    if (item.data[i*10 +: 10] == 10'h1FF) cls = 1;
end
foreach (item.data[i]) begin
    if (item.data[i*10 +: 10] == 10'h200) cls = (cls == 1) ? 0 : 2;
end
cur_sat = cls;  cg_sat.sample();
```

`cg_sat`（`:1724`）有 `none / pos / neg` 三个 bin，属于输出值分类。所以准确的说法是：
**已有输出边界值覆盖，但三处实现有错误，且不能证明真正发生了 signed10 饱和裁剪。**

| 缺陷 | 内容 |
| --- | --- |
| 概念混淆 | 把"输出 lane 等于边界"当成"发生了裁剪"。`+511` / `−512` 本身就是合法值，不是越界 |
| 遍历错误 | `item.data` 是 `logic [39:0]`，`foreach` 遍历 **40 个 bit 索引**；只有 `i=0..3` 落在合法 lane 上，`i=4..39` 是越界 part-select（返回 X） |
| 分类互斥 | 同一 beat 同时含 `+511` 与 `−512` 时，第二个循环把 `cls` 从 1 改回 0，判成"none"——同时存在正负边界反而丢失 |

**因此 B2 是替换旧 `cg_sat`，不是保留它再往上追加覆盖点。**

### 2.2 新模型（采纳审核建议，目标 bin 合计 56）

| 新组 | 采样单位 | 目标 bin |
| --- | --- | --- |
| `out_rail` | 每个被接收输出 beat 的四个 lane，**逐 lane** 采样 | `−512`、内部值 `[−511:510]`、`+511`，共 3 个 |
| `clip_signed10` | 每次有效 H 结果的四个**裁剪前** `signed [15:0]` lane | 正越界 `> 511`、负越界 `< −512`，共 2 个 |

逐 lane 采样后，同一 beat 同时含 `+511` 与 `−512` 会分别命中两边，不再被迫塞进
一个互斥的 beat 分类。裁剪也区分正负，**不用"钳位/未钳位"二分**——那样只测到一个
方向也可能显示全覆盖。

**口径推导**：`54 − 旧 sat 3 + out_rail 3 + clip 2 = 56`；按两个独立 covergroup
实现，组数 `7 − 1 + 2 = 8`。

（v1 提的 59 是"54 + 5"，保留了本应被替换的旧三项，已作废。55 对应"`out_rail`
只设正、负两个命中目标"的另一份清单，也不是算术错误——数字取决于模型，不能先定
数字再凑定义。）

**这 56 是项目自定义的目标 bin 汇总口径，不等于工具对 coverpoint/cross 的原生
加权覆盖率。** 报告时必须写清是哪一套口径。

### 2.3 采样规则

- **观测点**：`unified_its_wrapper.sv:1788` `horizontal_result_fire` 有效时，读取
  `kernel_out_data` 的四个 `signed[15:0]` 实参——这正是 `final_adapter()`
  （`:1086`）的入参。
- 使用**正确的采样沿与调度区域**，避免读到更新后的另一拍数据。
- **仅在 `FINAL_SATURATE != 0` 时**把越界记作"发生裁剪"。
- `+511`、`−512` 是合法边界，**不是越界**；`> 511`、`< −512` 才算裁剪。
- 四态数据**不能先转二态再判断**。
- 内部裁剪事件与外部输出接收事件**不同**：复位丢弃在途 TU 时两者次数不必相等，
  不能拿"次数相等"当验收条件。
- X/Z 不进入数值 bin，同时**报完整性错误并阻断通过**；复位与无效数据窗口明确屏蔽
  （不是"只计数、不影响判定"）。

### 2.4 验收判据

**分类器定向检查**（可离线，不依赖 DUT）：

| 项 | 要求 |
| --- | --- |
| 边界值 | `511`、`512`、`−512`、`−513` 四个值分别落对 bin |
| 同组组合 | 仅正越界、仅负越界、两者都有、都没有 |
| 四态 | 含 X/Z 的 lane 不进入数值 bin，且触发完整性错误 |
| 逐 lane | 同一 beat 内四 lane 不同取值分别计数，不互相覆盖 |

**真 DUT 验收**：

- 用合法输入命中正裁剪与负裁剪各至少一次，并核对最终 signed10 输出。
- 内部观测信号的层次可见性**先验证**再依赖。
- **不能用合成激励的分类器自检替代真 DUT 的裁剪覆盖。**
- 若零命中：可达目标必须补合法向量命；只写"激励缺口"不能宣布 B2 完成。
  确实不可达时，按证据调整目标并在文档里说明理由。
